# Changelog

All notable changes to Sentinel. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

- A second, page-level scrollbar appeared on longer pages and dragged the sidebar and top bar
  out of view. Absolutely positioned screen-reader labels were escaping the app shell; the shell
  and the content area now contain them, so only the content scrolls.

## [1.0.0] - 2026-10-04

The capstone core: a working end-to-end demo, from scope-checked scans through a
playbook to a PDF report, plus threat intelligence. Phases 0–8 and 12–14 are
complete; see [`docs/PROGRESS.md`](docs/PROGRESS.md) for the evidence behind
each one.

### Added
- **Foundation (Phase 0, #1):**
  - Docker Compose stack with least-privilege Postgres roles and isolated
    networks.
  - Health and readiness checks; CI covering backend, frontend, secret scan and
    a Compose smoke test.
- **Core backend (Phase 1, #7):**
  - Structured JSON logging with a mandatory redaction processor and request
    IDs.
  - Error model, Alembic migrations, the standard `ToolResult` schema, the
    tool registry, and the knowledge base that drives the educational
    translation engine.
- **Identity and audit (Phase 2, #11):**
  - Argon2id passwords, opaque cookie sessions with rotating refresh tokens,
    CSRF protection, lockout and rate limits.
  - Roles viewer, analyst and admin.
  - A hash-chained, append-only audit log with chain verification and security
    alerts.
- **Frontend shell (Phase 3, #12):** React 19 app, an API client with
  single-flight session refresh, the design system, and the admin audit viewer.
- **Client-side utilities (Phase 4, #13):** password analyzer, JWT inspector,
  hash tool and encoder/decoder. They run 100% in the browser, and tests prove
  no data leaves it.
- **Task infrastructure and DNS (Phase 5, #14):** Celery run lifecycle with
  quotas, live progress over WebSockets, run history, and the DNS & email
  security tool.
- **Scope policy and port scanner (Phase 6, #15):**
  - Admin scope policy with a hard denylist of Sentinel's own infrastructure,
    and an audited authorised-use acknowledgement.
  - TCP port scanner with banners, fingerprinting and NVD CVE matching.
  - Lab targets.
- **Header and TLS checker (Phase 7, #16):** SSRF-guarded HTTP checks, TLS and
  certificate analysis, and remediation snippets for nginx and Apache.
- **Playbook engine (Phase 12, #19):** YAML playbooks with safe step references,
  failure handling, cancellation and unified findings; the Web Defensive Audit.
- **Reporting (Phase 13, #20):**
  - PDF, CSV, JSON and plain-text exporters, generated by the worker.
  - SHA-256-verified and audited downloads.
  - Formula-injection-safe CSV, and an audit-trail export.
- **Production profile and polish (Phase 14, #21):**
  - `docker-compose.prod.yml`: nginx front end, runtime images, read-only
    containers.
  - Route-by-route authorisation matrix tests; Sentinel passes its own header
    checker.
  - A load-test script, env bootstrap scripts, and the README rewrite with
    screenshots.
- **Threat intelligence (Phase 8, #22):**
  - AbuseIPDB, VirusTotal and Shodan providers, each enabled by its API key.
  - Per-provider budgets, retries, caching and partial results, with the source
    named on every finding.
  - Private addresses are never sent to third parties.
  - A generic "tool availability" hook in the framework.

### Changed
- Phases 12–14 were built before 8–11 (ADR 0009).
- Cookie-less session refresh probes are no longer audited, which removes the
  audit noise from anonymous page loads (Phase 14, ADR 0011).

### Security
- STRIDE threat model with 74 numbered threats (`docs/threat-model.md`); all are
  mitigated except T16 (path traversal), which is reserved for Phases 10 and 11.
- Architecture decisions are recorded in ADR 0001–0012 (`docs/adr/`).
